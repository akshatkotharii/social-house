# Continuous learning system

Social House is designed to improve from incoming references and real outcomes, not accumulate an unread swipe file.

## Corpus-scale learning

Social House may learn from a structured content corpus, but it must not equate scale with truth. Bulk Instagram/Facebook browser scraping is not the default route. Use user-supplied references, saved collections, authorised account exports, permitted APIs or licensed datasets.

Run a stratified pilot before scaling. Score creative craft independently from public performance, compare posts within matched account/format/age cohorts, retain counterexamples, and send top, bottom and random samples through human review. Promote findings into skill rules only after repeated evidence or controlled tests.

Detailed schema, rubrics and nightly workflow: `skills/social-house/references/content-intelligence.md`.

## Input-to-change loop

1. Founder supplies a Reel, carousel, account, article, expert note, tool or output critique.
2. System separates observable evidence from claims and promotion.
3. Input is marked `adopt`, `test`, `sector-only`, `tool-route`, `reference-only` or `reject`.
4. Accepted learning changes the relevant skill rule, conditional reference, tool route, sector guide or behavioural test.
5. Change record explains what future output will do differently.
6. Real account results can promote, narrow or remove rule later.

This prevents two bad outcomes: storing knowledge without using it, and turning every interesting opinion into permanent doctrine.

## Where knowledge belongs

- **Core skill:** durable decisions required during most content jobs.
- **Format references:** Reel, carousel, cover, voice, trend and measurement workflows.
- **Sector packs:** textile-specific proof, audience, language and shot knowledge.
- **Brand Memory:** one company’s identity, claims, audience, creative history and performance.
- **Tool routes:** capability, trigger, fallback, access, cost and rights.
- **Research:** evidence, citations, disagreements and unresolved hypotheses.
- **Behaviour tests:** realistic tasks proving critical rules survive future edits.

## Learning is not model training

Current system learns through maintained instructions, references, brand data, tests and outcome records. It does not silently retrain a foundation model from links. This distinction matters: every accepted lesson remains inspectable, reversible and attributable.

## Minimal-friction founder workflow

Founder may paste only a URL and one sentence such as “great opening, weak branding.” System should inspect what is available, infer likely lesson, apply safe project updates and ask only when access or meaning blocks a responsible decision.

For private/inaccessible posts, request screenshot, screen recording or short description. Do not pretend content was reviewed.
